# pycdc-rapid 贡献指南

## 提交 Issue

Issue 必须包含：

- 出问题的 `.pyc` 文件。请先清除敏感信息，但必须提供仍可复现问题的最小 PYC。
- 生成该 PYC 的 Python 版本；若不是 CPython，还应说明实现和版本。
- 清晰的问题说明：执行命令、预期结果、实际结果，以及问题属于崩溃、警告还是错误还原。
- 是否已使用最新 `pycdc-rapid` 提交或 Release 复现。

可选择性提供 `pycdc`/`pycdas` 的 stderr 日志、反汇编结果和生成源码。它们对栈、块、无效 opcode 与 marshal 读取类问题尤其有帮助。

## 提交 Pull Request

每个 PR 必须包含：

- 聚焦的测试 Python 源文件（`.py`）和由目标 Python 版本生成的对应 PYC。
- 受影响的 Python 字节码版本、恢复功能的简要说明，以及已知的 best-effort 限制。
- 构建与验证命令；可用时应包含 `pycdas`、`pycdc` 和相关语法/回编译检查。

若改动涉及较大范围的字节码解码、栈/块恢复、AST 构建或版本支持，提交前还必须反编译项目当前的全部 PYC。这包括项目中已跟踪的测试夹具，以及维护开始时使用的四个本地 PYC 输入文件。这四个文件仅用于本地测试：不得复制到仓库的 PYC 测试目录，也不得提交。请报告命令、退出码汇总与仍存在的诊断；不要隐藏已知的不完整输出。

保持改动小而易审查。除非被明确批准为测试夹具，不要提交 build 目录、可执行文件、对象文件、自动生成的 PYC、反编译输出或个人本地文件。
